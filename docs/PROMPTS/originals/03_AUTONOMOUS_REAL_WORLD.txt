6.3. Как организовать речевой сигнал
Приоритет способов:

Способ A — реальный физический аудиотракт

Если тестовая Windows-среда имеет управляемый аудиовыход и физический микрофон, организуй подачу речи таким образом, чтобы VoxType получал сигнал именно через свой обычный путь записи.

Учитывай акустические искажения.

Способ B — виртуальный аудиокабель

Если физический вариант недоступен, настрой разрешённое виртуальное аудиоустройство:

Audio playback → Virtual audio input → PortAudio capture → VAD → ASR → VoxType UI → Windows text insertion

Это предпочтительный автономный вариант для воспроизводимого end-to-end тестирования.

Способ C — воспроизведение через тестовое capture-устройство

Используй поддерживаемый устройством loopback/capture маршрут, если он действительно проходит через обычный audio pipeline приложения.

Не подменяй его прямым вызовом функции транскрибации.

Нельзя:
- Напрямую записывать эталонный текст в поле.
- Подставлять готовую расшифровку вместо работы ASR.
- Вызывать только transcribe(audio) и называть это пользовательской диктовкой.
- Отключать VAD и основные этапы pipeline исключительно ради зелёного результата.
- Считать TTS-проверку эквивалентом живого человеческого голоса.
Синтезированная речь допустима как автономный воспроизводимый тестовый сигнал. Если доступно использование записей настоящей человеческой речи, обязательно дополни ими тестовый набор.

Не изменяй системное аудиоустройство пользователя без безопасного восстановления прежних настроек.
